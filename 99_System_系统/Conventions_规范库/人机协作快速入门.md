# 人机协作快速入门

人机协作最容易失败的原因，不是 Prompt 不够长，而是把不同大小的事情用同一种方式交给 AI。

## 先判断是哪一档

| 档位 | 适合什么事 | 怎么做 |
|---|---|---|
| 对话 | 问概念、改一段话、发散想法 | 直接说问题和期望结果 |
| 任务 | 一次会话能完成、只有一个明确交付物 | 使用 [[99_System_系统/Templates_模板库/T_AI任务卡|AI 任务卡]] |
| 目标 | 多步骤、要查资料或改很多文件、需要长时间自主执行 | 先用 `spec-builder` 或 `leader` 生成规格/任务书，再交给执行 Agent |

> [!tip]
> 能用一句话说清且改错也容易撤销，就直接对话。影响范围越大、运行时间越长，越要先写规格。

## 一个可靠的协作循环

1. **说结果**：先说最后要得到什么，不急着替 AI 决定实现方法。
2. **给现场**：让 AI 读取相关笔记、目录、旧方案或数据，避免凭空猜。
3. **划边界**：明确哪些能改、哪些不能碰，哪些操作必须再次确认。
4. **定验收**：写出你怎么判断它真的做成了。
5. **让它执行并验证**：结果后面必须跟证据、检查结果或来源。
6. **只沉淀有效部分**：保留最终结果、关键决策和可复用方法，不囤完整聊天记录。

## 三种档位怎么用

### 1. 对话：小事直接说

```text
请把下面这段说明改得更简洁，保留事实和原语气，控制在 150 字内。
```

只要补充“材料 + 期望结果 + 关键限制”即可，不需要套复杂模板。

### 2. 任务：用一张任务卡

在项目目录中新建笔记，套用 [[99_System_系统/Templates_模板库/T_AI任务卡|AI 任务卡]]。填好“结果、现场、边界、验收”后，把其中的任务区直接发给 AI。

适合整理资料、写一份方案、修改一组笔记、完成一个小功能等单次交付。

### 3. 目标：先生成规格或任务书

当任务会跨多轮、跨文件，或者你准备让 Agent 自主运行较长时间时，不要只发一句“帮我做完”。先让专门的 skill 帮你把想法问清楚：

- `spec-builder`：适合把模糊想法整理成需求、设计和任务拆分。同名实现较多，可使用你信任的版本；[这里是一个公开实现](https://github.com/NeverSight/learn-skills.dev/tree/main/data/skills-md/adaptationio/skrillz/spec-builder)。
- [`leader`](https://github.com/KKKKhazix/khazix-skills/tree/main/leader)：适合把一句想法变成能交给 Agent 独立执行和验收的目标任务书。

安装方式取决于所用 Agent。最简单的做法是把 skill 链接发给支持 Agent Skills 的 AI，并明确说“安装这个 skill”；安装前先阅读 `SKILL.md` 和它包含的脚本。

生成规格后先由人检查三件事：**目标有没有写偏、禁止事项够不够、完成标准能不能验**。确认后再交给执行 Agent。

## 做完一批任务后：整理知识库

连续完成一批任务、结束一个项目阶段，或发现 README、规范和实际内容开始对不上时，建议使用 [`neat-freak`](https://github.com/KKKKhazix/khazix-skills/tree/main/neat-freak)。

它适合做阶段性收口：检查文档与现状是否一致、合并重复说明、删除过期指引，并让下次接手的人或 Agent 能快速找到现役答案。可以直接对 AI 说：

```text
用 neat-freak 整理这个知识库，核对 README、规范和当前目录，
合并重复内容，列出需要我确认的删除项，不要直接删除私人笔记。
```

## 结果放回哪里

| 内容 | 放置位置 |
|---|---|
| 某个交付物、过程决策和验证记录 | 对应的 `01_Projects_项目` |
| 已验证、可跨项目复用的方法 | `02_Knowledge_知识库` |
| 通用协作规则、Agent 规则和模板 | `99_System_系统` |
| 已结束项目的完整上下文 | `03_Archive_归档` |
| 暂时无法判断用途的内容 | `00_Inbox_收集箱` |

## 最低安全线

- 不提供密码、Token、恢复码或无关的个人信息。
- 事实要求来源；明确区分事实、推断和未知。
- 修改文件后查看差异与验证结果，不只看 AI 的总结。
- 删除数据、公开发布、付款或联系他人前，必须再次确认。
- 医疗、法律、财务和现实安全问题由合格的人做最终判断。

给文件型 Agent 使用的规则模板见 [[99_System_系统/Conventions_规范库/AGENTS|AGENTS.md]]。
