# 人机协作快速入门

高效协作不是让 AI 代替思考，而是让人和 AI 各自负责最擅长的部分：

| 人负责 | AI 负责 |
|---|---|
| 目标、取舍、边界和最终责任 | 检索、整理、生成方案、执行重复工作和检查 |
| 提供真实背景与隐性约束 | 暴露假设、不确定性和风险 |
| 判断结果是否值得采用 | 提供可验证的过程与证据 |

## 第一次协作：只写清五件事

复制下面这段，把空白处补完整：

```text
目标：我最终想得到什么？
背景：AI 必须知道哪些上下文？
约束：哪些事不能做？时间、格式或范围有什么限制？
交付：请以什么形式给我结果？
验收：什么条件满足才算完成？

工作方式：先检查已有材料并说明理解；信息不足时列出假设；
完成后给出验证结果、剩余风险和需要我决定的事项。
```

也可以直接使用 [[99_System_系统/Templates_模板库/T_人机协作任务|人机协作任务模板]]。

> [!example] 模糊请求
> “帮我整理一下这些资料。”

> [!success] 可执行请求
> “把项目目录中的 8 篇访谈整理成一份用户痛点清单。保留原话出处，不补造事实；按出现频率排序，用 Markdown 表格交付。每个结论至少能追溯到一篇原文，无法确认的内容标记为待核实。”

## 五步工作流

### 1. 定义结果

先写验收条件，再讨论方法。没有验收条件时，AI 很容易产出“看起来完整、实际上没解决问题”的内容。

### 2. 先读后做

让 AI 先检查已有笔记、文件和约束，复述它对任务的理解。涉及修改时，先确认影响范围；小而可逆的任务可以直接执行。

### 3. 小步交付

复杂任务分成“调查 → 方案 → 执行 → 验证”。每一步都产生可检查的结果，不把所有判断压到最后。

### 4. 对抗式检查

完成后再问一次：

```text
请站在反对者、首次使用者和维护者三个角度检查结果。
重点寻找错误假设、遗漏边界、无法验证的说法和可能造成损失的操作。
发现问题就修正，并列出仍然存在的风险。
```

### 5. 沉淀有效部分

不必保存每段对话，只保留对以后有用的结果：

| 内容 | 放置位置 |
|---|---|
| 某个交付物的 AI 产出与决策 | 对应的 `01_Projects_项目` |
| 已验证、可跨项目复用的方法 | `02_Knowledge_知识库` |
| 通用协作规则和任务模板 | `99_System_系统` |
| 已结束项目的完整上下文 | `03_Archive_归档` |
| 暂时无法判断用途的内容 | `00_Inbox_收集箱` |

## 四种常用协作方式

| 场景 | 怎么要求 AI |
|---|---|
| 探索 | 给出 2–3 个真正不同的方案、依据、代价和适用条件 |
| 执行 | 明确允许修改的范围、禁止事项、交付物和验收方式 |
| 审查 | 不复述结果，专门寻找反例、遗漏、风险和验证缺口 |
| 提炼 | 区分事实、推断和经验，把可复用结论链接回原始材料 |

## 安全边界

- 不向 AI 提供密码、Token、恢复码或无关的个人信息。
- 涉及医疗、法律、财务或现实安全时，AI 只能辅助整理，最终判断交给合格的人。
- 要求事实附来源，并明确区分事实、推断和未知。
- 让 AI 修改文件或代码后，查看差异和验证结果，不只看它的总结。
- 删除数据、公开发布、付款或替你联系他人前，必须再次确认目标和范围。

## 15 分钟练习

1. 选一个今天真实要完成的小任务。
2. 用五项框架写清请求。
3. 让 AI 先复述任务，再执行。
4. 用对抗式检查提示复查一次。
5. 把最终结果放入正确目录，只沉淀真正可复用的方法。

根目录的 `AGENTS.md` 是给文件型 AI Agent 使用的默认边界，可按自己的工作方式修改。
