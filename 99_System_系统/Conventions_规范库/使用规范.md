# 知识库使用规范

## 分流

| 判断问题 | 位置 |
|---|---|
| 现在还无法判断用途吗？ | `00_Inbox_收集箱` |
| 有明确目标、交付物或结束条件吗？ | `01_Projects_项目` |
| 以后会按主题查阅、学习或复用吗？ | `02_Knowledge_知识库` |
| 已结束，只需保留上下文吗？ | `03_Archive_归档` |
| 是维持知识库运行的配置或资源吗？ | `99_System_系统` |

一篇笔记只选择一个主要位置，跨主题关系用双链表达。

## 工作流

1. 捕获：不确定的内容先放 Inbox。
2. 整理：处理 Inbox，使用模板补足上下文。
3. 连接：链接直接相关的笔记；需要导航时再建立 MOC。
4. 使用：让知识进入项目、文章、产品或决策。
5. 提炼：把项目中可复用的结论写入 Knowledge，并链接回项目。
6. 归档：结束的完整上下文移入 Archive。

## 命名

- 知识笔记直接写清主题，不强制日期。
- 项目文件夹使用项目名称，入口可命名为 `项目首页.md`。
- MOC 使用 `MOC_主题名称.md`。
- 日记使用 `YY-MM-DD.md`。
- 避免“新建笔记”“未命名”“随便记记”等无法检索的名称。

## Properties 与标签

- 文件夹决定主要位置，标签只补充状态和类型。
- 推荐状态：`status/seed`、`status/growing`、`status/evergreen`。
- 推荐类型：`type/note`、`type/moc`、`type/project`、`type/review`、`type/reference`、`type/guide`。
- 标签不能改善搜索、过滤或维护时，不要添加。

## 维护节奏

| 频率 | 动作 |
|---|---|
| 每日 | 捕获内容，清理必要的 Inbox 项 |
| 每周 | 更新项目下一步，提炼可复用认识 |
| 每月 | 归档结束内容，删除无价值内容 |
| 按需 | 当同一主题确实难以导航时创建 MOC |
